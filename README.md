# 모아 — 대학생 팀플 매니저

자료부터 발표까지 팀의 흐름을 한곳에서 연결하는 한국어 협업 웹앱입니다.

## 구현 기능

- 주제 맵: 대주제 → 소주제 → 자료·대본을 연결선과 카드로 표시, 소주제 추가·접기·검색
- 자료 및 발표 장면의 사용자 지정 이미지 썸네일 (JPG/PNG/WebP, 최대 2MB)
- 카드 클릭으로 본문·대본·첨부 이미지/PDF 보기, PPT 등은 다운로드 링크 제공
- 이메일 회원가입, 인증 코드 확인, 로그인 및 세션 갱신
- 프로젝트 생성, 128비트 초대 코드와 초대 링크로 참여
- 팀 역할 직접 지정, 작업 담당자·마감일·진행 상태
- 완료 작업 수와 등록 자료 수에 기반한 기여 현황 / 소주제별 진행률
- 소주제별 자료 검색, 원문 링크, 발췌 문장 강조, 최대 10MB 비공개 파일 업로드
- 등록 자료를 소주제별로 묶어 발표 장면 초안 생성
- 슬라이드 내용·대응 자료·대본 3열 화면
- 피드백 게시판과 15초 간격 팀 데이터 갱신
- 현재 화면을 브라우저 인쇄의 ‘PDF로 저장’으로 내보내기
- 로그인 없이 사용하는 저장되지 않는 샘플 체험

## 실행과 배포

외부 npm 의존성이 없는 Vanilla JavaScript 앱입니다. Node.js 22 이상을 사용합니다.

```sh
npm run check
npm run build
```

Vercel에서 저장소를 연결하고 Build Command `npm run build`, Output Directory `public`, Framework `Other`로 설정합니다. `/api/config`는 Vercel Node 함수입니다.

환경 변수 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`를 Vercel에 설정합니다. publishable 키만 브라우저로 전달하며 service role 키는 사용하지 않습니다. Supabase 초기 스키마는 `db/schema.sql`에 있습니다. 이 파일은 새 데이터베이스에 한 번 적용하는 초기 스키마로, 반복 적용용 파일이 아닙니다.

기존 초기 버전의 데이터베이스를 업그레이드할 때는 `db/upgrade-topic-map.sql`을 한 번 적용합니다. 새 데이터베이스에는 `db/schema.sql` 다음 해당 업그레이드 SQL을 순서대로 적용합니다. 기존 자료의 소주제를 그대로 읽으며, 썸네일과 원본 첨부파일은 별도로 저장합니다. PPT의 브라우저 미리보기는 지원하지 않습니다.

## 사용 순서

1. 이메일로 가입하고 인증 메일의 코드를 입력합니다. 메일에 코드가 없다면 인증 링크를 누른 후 로그인하세요.
2. ‘만들기 / 참여하기’에서 프로젝트를 만듭니다.
3. ‘팀원 초대’의 코드 또는 링크를 팀원에게 전달합니다.
4. 작업과 역할을 나누고 자료실에 근거를 모읍니다.
5. 발표 스튜디오에서 자료와 대본을 연결합니다.

## 보안 및 협업 동작

모든 프로젝트 데이터는 Supabase RLS로 팀원에게만 공개됩니다. 팀원 역할 변경은 본인 또는 팀장만 가능합니다. 역할 이름은 설명용이며 팀장 권한을 변경하지 않습니다. 초대 코드를 가진 로그인 사용자는 참여할 수 있으므로 팀원에게만 공유하세요. 첨부파일은 비공개 버킷에 저장하고 만료 시간이 있는 링크로 읽습니다. 같은 항목을 동시에 수정하면 먼저 저장된 변경을 감지하고 다시 편집하도록 안내합니다.

## 현재 범위와 제한

발표 흐름 구성은 소주제 기반 규칙형 초안이며 생성형 AI는 아닙니다. 업로드한 PPT 파일의 자동 해석이나 실제 슬라이드 렌더링은 제공하지 않으며 발표 스튜디오에는 직접 작성한 슬라이드 내용이 표시됩니다. 형광펜은 발췌 텍스트의 일치 문장을 강조하며 원본 PDF/웹페이지를 수정하지 않습니다. 알림은 피드백 확인 진입점이고 읽음 처리·브라우저 푸시·이메일 알림은 없습니다. 기여도는 활동 수의 참고 지표로 작업 품질이나 실제 노력을 평가하지 않습니다. 파일 교체 시 기존 파일 정리는 자동화되지 않았습니다.
